# ADR-0008:训练能力纳入产品范围(编译期反向图路线)

- 状态:已接受
- 日期:2026-07-12
- 关联铁律:#1 编译优先 / #5 两级复用
- 关联规则:ARCH-012、ARCH-020、ARCH-041、BUILD-011

## 背景

产品范围此前未定义训练能力(PLAN.md 开放问题 Q3),全部架构文档零覆盖。
2026-07-12 项目所有者裁定:训练能力(自动微分与优化器)纳入产品范围。
训练涉及 IR 与算子系统的连带扩展,属影响面大的方向性决策,先行立档。

## 决策

训练采用**编译期反向图**路线,分三个里程碑(M16–M18)交付:

- 自动微分 = 反向模式(reverse-mode),实现为**编译期图→图变换**:由前向
  Graph 在编译期生成反向 Graph;与铁律 #1 及 ADR-0001 一致,运行时
  tape/逐算子记录不作为主线(调试用途须另行依 ARCH-011 准入类别裁决)。
- 可微算子的梯度规则经注册机制接入(注册面形态——OpSchema 扩展字段或
  独立注册表——在 M16 设计文档定案),禁止在图变换内硬编码算子分支
  (铁律 #5 可扩展性要求,与 FRAME_REGISTER_OP 同构)。
- v0 训练最小集:v0 六算子(add/mul/relu/matmul/sum/square)梯度 +
  mse_loss 损失算子 + SGD 优化器;验收基准 = 小规模 MLP 在 cpu 参考
  后端上**经编译路径**执行训练并收敛(确定性种子,loss 低于阈值)。
- 分期:M16 训练架构设计(docs/architecture/autograd.md,先文档后代码);
  M17 反向图生成 + 梯度算子(解析梯度 ≡ 数值微分,BUILD-011 容差);
  M18 优化器与训练闭环(建议版本锚 v1.1)。
- 判定方法:M16 起 `ls docs/architecture/autograd.md` 存在,其中每条
  `TODO(FRAME-DESIGN)` 待办自带完成判据;M17/M18 验收以 tests/cpp/
  对应数值校验与收敛用例通过为准(`ctest --preset cpu-only` 全绿)。

## 备选方案

- 运行时 tape 自动微分(eager 逐算子记录):实现门槛低、生态惯例;但与
  铁律 #1 及 ADR-0001 的编译优先路线冲突,eager 仅为调试/回退路径——否决。
- 推迟至 v2.0 与动态 shape 等一并裁决:范围最小;但训练是框架完整性的
  方向性能力,且编译闭环(M7)已就绪,继续推迟无技术收益——经裁定否决。

## 后果

- 正面:产品范围明确;反向图完全复用既有 IR/管线/编译执行基建,不新增
  执行模式(ARCH-012 不触发)。
- 负面与代价:IR 与算子系统需连带扩展(多输出关联、参数与停止梯度标记),
  M16 设计期逐项裁决;若涉及更改 IR 核心对象模型(Graph/Node/Value/
  Attribute 类型集合),按触发清单情形 3 另立专项 ADR;此后每新增算子,
  梯度覆盖成为长期维护面(无梯度算子须显式声明不可微)。
- 跟进:PLAN.md 增补 M16–M18 与版本锚 v1.1(本次);milestones.md 增补
  三节详单(本次);docs/architecture/autograd.md 于 M16 交付;README
  状态声明随 M18 收口更新。
