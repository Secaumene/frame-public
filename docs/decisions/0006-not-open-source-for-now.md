# ADR-0006:暂不开源

- 状态:被 ADR-0023 取代
- 日期:2026-07-04
- 关联铁律:#5
- 关联规则:REUSE-010

## 背景

项目处于骨架与治理体系搭建期,是否开源、以何种许可证开源尚未决定。许可证一旦
随公开发布授予即难以收回;而第三方依赖的许可证准入标准必须现在就定,否则将来
决定开源时可能被迫剥离替换依赖、大规模返工。

## 决策

暂不开源,版权保留:

- 仓库不放置 LICENSE 文件;
- README.md 标注「未开源、版权保留(All rights reserved)」;
- pyproject.toml 不写 license 字段;
- 第三方依赖的许可证白名单(docs/standards/reuse-policy.md)仍按「可开源」标准
  执行:Apache-2.0 / MIT / BSD 直接可用,LGPL 需 ADR,GPL/AGPL 禁止——确保将来
  决定开源时无需替换依赖;
- 重评条件:决定对外发布时,新立 ADR 裁决许可证选择,并更新本篇状态与索引表。

判定方法:仓库根 `ls LICENSE*` 无命中;`grep -E '^license' pyproject.toml`
无命中;README.md 含版权保留声明;以上三项纳入 review 检查表。

## 备选方案

- 立即以 Apache-2.0 开源:优点是社区惯例、便于吸引使用与外部贡献;缺点是 API
  远未稳定、发布节奏未定,过早承担公开维护义务。否决(现阶段);开源本身不排除,
  留待重评。
- 保持私有且放开 GPL 类依赖:优点是可选库范围更大;缺点是一旦将来开源需整体
  剥离传染性依赖,返工成本不可控。否决。

## 后果

- 正面:保留全部发布选项;依赖白名单与开源标准前瞻对齐,切换成本最小化。
- 负面:不可公开分发,无法接受外部贡献;README 须有明确声明以免误用。
- 跟进:README.md 落版权保留声明;pyproject.toml 保持无 license 字段
  (随验证方案的 tomllib 解析步骤人工核对)。
